# LNIS AFS Validator 수동 인수시험

## 사전 기록

- 앱 버전/빌드 일시:
- `LnisAfsCodec.dll` SHA-256:
- 송신/수신 PC 주소:
- 데이터/결과 포트:
- 입력 `capture.graw` SHA-256:
- 논리 PRN 식별값(기본 8):

## 송신부 GNSS COM 입력

- 장치 관리자에 표시된 COM 포트와 Baud rate를 기록한다.
- 프로토콜 미정 모드에서 수집 후 `serial-input.bin` 크기가 증가하고 중지 시 파일이 정상 닫히는지 확인한다.
- 장비 프로토콜 어댑터가 제공되면 관측 Epoch·항법 Update 카운터와 `capture.graw` 생성을 확인한다.
- 생성된 `capture.graw`가 같은 송신부의 입력 경로에 자동 설정되는지 확인한다.
- 잘못된 COM 이름, 사용 중인 포트와 지원하지 않는 Baud rate 오류가 화면에 표시되는지 확인한다.

## Test A 정상 종단간

- 수신부를 먼저 시작한 뒤 송신부 Drop Rate를 0%로 실행한다.
- 수신 결과가 Pass이고 원본/복원 길이, 레코드 수, SHA-256이 모두 일치하는지 확인한다.
- `result.json`, `metrics-summary.csv`, `metrics-timeseries.csv`, `reconstructed.graw` 생성을 확인한다.

## Test B/C 코덱 성능

- Random과 Burst를 각각 오류 심볼 `1,2,5,10,20,50,100`, 조건별 100회로 실행한다.
- 같은 Seed로 재실행했을 때 반전 인덱스와 요약 결과가 동일한지 확인한다.
- SB2/SB3/SB4 LDPC 성공률, CRC 통과율과 전체 프레임 복원률이 화면·CSV·JSON에 기록되는지 확인한다.

## Test D 재동기

- SyncLoss 오류 개수 1~68 범위에서 실행한다.
- 손상 프레임 거부율, 다음 SP 재탐색률, Decode 복구율과 논리 복구시간을 확인한다.

## Test E UDP Drop

- Drop Rate 10%, 고정 Seed로 두 번 실행해 계획된 제거 패턴이 같은지 확인한다.
- SessionStart/End와 Result가 유지되고 시험이 정상 종료되는지 확인한다.

## 실패 경로

- 잘못된 파일, 같은 포트, 범위 밖 Drop Rate가 실행 전에 거부되는지 확인한다.
- 수신 대기와 송신 결과 대기 중 취소가 정상 동작하는지 확인한다.
- 방화벽 차단 또는 수신부 미실행 시 송신부에 타임아웃 오류가 표시되는지 확인한다.
