# LANS AFS 오픈소스 코드 분석 및 네트워크 검증 활용 가이드

## 1. 문서 목적

이 문서는 LANS(Lunar Augmented Navigation Service)의 AFS(Augmented Forward Signal)를 생성하고 수신하는 다음 두 오픈소스의 역할과 처리 흐름을 설명한다.

- [LANS-AFS-SIM](https://github.com/osqzss/LANS-AFS-SIM): AFS 송신 신호 생성기
- [PocketSDR-AFS](https://github.com/osqzss/PocketSDR-AFS): AFS 소프트웨어 수신기

두 프로젝트를 함께 사용하면 AFS 항법 데이터가 채널 부호화, 인터리빙, 변조 및 I/Q 샘플 생성을 거쳐 송신되고, 수신 측에서 다시 복조·복호되는 종단 간 흐름을 시험할 수 있다.

> 핵심: LANS-AFS-SIM은 단순한 AFS 프레임 생성기가 아니라, 프레임 생성과 채널 코딩을 내부에 포함한 **기저대역 I/Q 신호 생성기**이다. PocketSDR-AFS는 그 I/Q 신호에서 원래 항법 데이터를 복원하는 **소프트웨어 정의 수신기**이다.

---

## 2. 오픈소스별 역할

| 구분 | LANS-AFS-SIM | PocketSDR-AFS |
|---|---|---|
| 위치 | 송신 측 | 수신 측 |
| 주요 입력 | 시각, 궤도·항법 데이터, 시뮬레이션 설정 | 파일 또는 SDR에서 수신한 I/Q 샘플 |
| 주요 출력 | AFS 기저대역 I/Q 샘플 파일 | 복호된 AFS 항법 데이터와 수신 결과 |
| 채널 코딩 | BCH/LDPC 부호화 | BCH/LDPC 복호 |
| 인터리빙 | 인터리빙 수행 | 디인터리빙 수행 |
| 신호 처리 | BPSK 매핑, PRN 확산, 샘플 생성 | 획득, 추적, 역확산, 심볼 판정 |
| 최종 목적 | 시험용 AFS 송신 신호 생성 | AFS 수신 알고리즘 및 항법 성능 검증 |

## 3. 전체 송수신 처리 흐름

### 3.1 송신 측: LANS-AFS-SIM

```text
AFS 항법 데이터
→ 프레임 구성 및 CRC 추가
→ BCH 또는 LDPC 채널 부호화
→ 인터리빙
→ BPSK 심볼 매핑
→ PRN 코드 확산
→ 오버샘플링 및 I/Q 생성
→ 기저대역 I/Q 파일 출력
```

### 3.2 수신 측: PocketSDR-AFS

```text
I/Q 샘플 입력
→ 신호 획득 및 추적
→ PRN 역확산
→ BPSK 심볼 추출
→ 디인터리빙
→ BCH 또는 LDPC 복호
→ CRC 검사
→ AFS 항법 데이터 복원
```

송신기와 수신기의 처리는 서로 반대 방향이다. 송신기는 원본 데이터에 복구용 정보를 추가하고 무선 신호 형태로 변환하며, 수신기는 신호에서 심볼을 추출한 뒤 원본 데이터를 복원한다.

## 4. 부호화 코드의 역할

채널 부호화는 전송 중 일부 비트가 손상되더라도 원본 데이터를 복원할 수 있도록 패리티 비트를 추가하는 과정이다.

### 4.1 BCH와 LDPC

AFS의 데이터 구간에 따라 BCH 또는 LDPC 계열의 오류 정정 부호가 사용된다.

- **BCH**: 비교적 짧은 블록의 오류 검출·정정에 사용한다.
- **LDPC**: 여러 패리티 검사 관계를 이용해 손상된 비트를 반복적으로 추정하고 복원한다.
- **CRC**: 복호가 끝난 결과에 오류가 남아 있는지 최종 확인한다.

LDPC의 개념적인 동작은 다음과 같다.

```text
원본 정보 비트
→ 패리티 비트 계산 및 추가
→ 정보 비트 + 패리티 비트로 구성된 코드워드 전송
→ 수신 측에서 패리티 관계 검사
→ 의심되는 비트를 반복 보정
→ CRC로 최종 결과 확인
```

LDPC 패리티는 단순히 오류 존재 여부만 알려주는 값이 아니다. 여러 비트가 서로 겹치는 다수의 검사식에 포함되므로, 어떤 검사들이 동시에 실패했는지를 이용해 오류 가능성이 높은 비트를 찾을 수 있다.

## 5. 인터리빙 코드의 역할

인터리빙은 비트를 추가하거나 삭제하지 않고 **전송 순서만 재배열**한다.

```text
인터리빙 전: A1 A2 A3 B1 B2 B3 C1 C2 C3
전송 순서:   A1 B1 C1 A2 B2 C2 A3 B3 C3
```

전송 중 연속된 여러 비트가 손상돼도 수신 측에서 디인터리빙하면 오류가 여러 코드 블록에 분산된다. 그 결과 특정 코드 블록에 오류가 몰리는 현상이 줄어들어 BCH나 LDPC가 복구하기 쉬워진다.

```text
송신: 부호화 → 인터리빙
수신: 디인터리빙 → 복호
```

## 6. 심볼 매핑과 I/Q 생성의 차이

### 6.1 심볼 매핑

BPSK에서는 논리 비트를 두 개의 신호 상태로 대응시킨다.

```text
비트 0 → +1 심볼
비트 1 → -1 심볼
```

심볼 매핑 자체는 정보 비트 수를 늘리지 않는다. 비트를 송신 신호의 상태로 표현하는 규칙을 정하는 단계이다.

### 6.2 PRN 확산과 I/Q 생성

심볼에 PRN 코드를 적용하면 심볼 하나가 많은 칩으로 확장된다. 여기에 샘플링률에 따른 오버샘플링과 I/Q 표현까지 적용되면서 저장 및 전송해야 하는 데이터가 크게 증가한다.

```text
원본 비트
→ 채널 부호화로 증가
→ 인터리빙: 개수 변화 없음
→ 심볼 매핑: 정보량 변화 없음
→ PRN 확산: 칩 수 크게 증가
→ 오버샘플링·I/Q 생성: 샘플 수와 바이트 수 크게 증가
```

따라서 I/Q 파일은 AFS 메시지나 AFS 프레임 자체가 아니다. AFS 프레임을 실제 수신기가 처리할 수 있는 연속 기저대역 신호 샘플로 변환한 결과이다.

## 7. AFS 프레임과 심볼 수

확인된 AFS 항법 프레임은 `6,000개 심볼`로 구성되며, 수신 처리에서는 앞쪽 동기 패턴 `68개 심볼`을 함께 다룬다.

```text
동기 패턴        68 symbols
AFS 항법 프레임  6,000 symbols
합계             6,068 symbols
```

BPSK 심볼을 `0/1` 한 비트로 표현해 패킹한다고 가정하면 다음 크기가 된다.

```text
6,000 symbols ÷ 8 = 750 bytes
6,068 symbols ÷ 8 = 758.5 bytes → 저장 시 약 759 bytes
```

이는 `+1/-1`을 각각 정수나 실수로 저장하는 것이 아니라, 심볼의 부호 상태를 한 비트로 패킹했을 때의 크기이다.

## 8. I/Q 없이 Wi-Fi UDP로 보내는 확장 구조

### 8.1 가능한 구조

I/Q 신호 처리까지 시험하지 않고, 채널 부호화와 인터리빙 결과의 네트워크 전달을 시험하려면 다음과 같은 별도 모드를 추가할 수 있다.

```text
AFS Frame
→ CRC
→ BCH/LDPC 부호화
→ 인터리빙
→ BPSK 심볼 상태를 0/1로 비트 패킹
→ Wi-Fi UDP 전송
→ 비트 언패킹
→ 디인터리빙
→ BCH/LDPC 복호
→ CRC 검사
→ AFS Frame 복원
```

`6,068개`의 이진 심볼을 패킹하면 약 `759바이트`이므로, 적절한 애플리케이션 헤더와 CRC32를 추가해도 일반적인 MTU 1,500바이트 이내의 UDP 데이터그램 하나에 넣을 수 있다.

예시 패킷 구조는 다음과 같다.

| 필드 | 목적 |
|---|---|
| Magic / Version | 패킷 종류 및 프로토콜 버전 확인 |
| StreamId | 여러 시험 스트림 구분 |
| FrameId | AFS 프레임 식별 |
| SequenceNumber | 전송 순서 및 유실 확인 |
| SymbolCount | 포함된 심볼 개수 확인 |
| CodingType | BCH/LDPC 등 부호화 방식 표시 |
| MappingType | BPSK 등 심볼 매핑 방식 표시 |
| PayloadLength | 실제 payload 길이 확인 |
| PackedSymbols | 비트 패킹된 심볼 데이터 |
| CRC32 | UDP 애플리케이션 데이터 무결성 확인 |

### 8.2 반드시 구분할 점

이 방식은 **AFS 신호 자체를 Wi-Fi로 송신하는 것이 아니다.** AFS 채널 코딩이 끝난 디지털 심볼 데이터를 UDP payload에 담고, 실제 무선 송신은 Wi-Fi의 IEEE 802.11 규격이 담당한다.

따라서 이 모드로 검증할 수 있는 것은 다음과 같다.

- AFS 프레임 구성
- BCH/LDPC 부호화 및 복호
- 인터리빙 및 디인터리빙
- 심볼 패킹 및 언패킹
- UDP 송수신
- 프레임 무결성 및 데이터 일치 여부

반면 다음 항목은 검증할 수 없다.

- PRN 확산과 역확산
- AFS 반송파 및 실제 변조 신호
- 잡음, 도플러, 주파수 편차의 영향
- 신호 획득 및 추적
- SDR 및 RF 수신 성능
- PocketSDR-AFS의 전체 I/Q 수신 체인

## 9. UDP 유실과 LDPC의 한계

LDPC는 수신된 코드워드 안에서 일부 비트가 잘못됐을 때 복구에 도움을 준다. 그러나 Wi-Fi 링크 계층에서 손상된 프레임은 보통 폐기되므로, 애플리케이션에서는 비트 몇 개가 틀린 UDP 패킷보다 **UDP 데이터그램 전체가 도착하지 않는 현상**을 더 자주 보게 된다.

```text
일부 수신 비트 오류 → LDPC가 복구할 수 있음
UDP 패킷 전체 유실 → 해당 패킷 내부 LDPC만으로 복구할 수 없음
```

따라서 패킷 전체 유실에 대응하려면 AFS 내부 LDPC와 별도로 다음 방법 중 하나가 필요하다.

- 같은 프레임을 2~3회 반복 송신
- 여러 UDP 패킷에 대한 패킷 단위 FEC 추가
- 유니캐스트 모드에서 ACK 및 재전송 프로토콜 구현
- 순번을 이용한 유실 감지 후 결과를 `Inconclusive`로 판정

## 10. 권장 시험 모드

### Mode A: Channel Coding Network Test

```text
AFS Frame
→ BCH/LDPC
→ 인터리빙
→ 심볼 비트 패킹
→ Wi-Fi UDP
→ 디인터리빙
→ BCH/LDPC 복호
→ AFS Frame 비교
```

목적:

- 채널 코딩 알고리즘 검증
- UDP 네트워크 송수신 검증
- 송신·수신 프레임 일치 여부 확인

### Mode B: Signal End-to-End Test

```text
AFS Frame
→ LANS-AFS-SIM
→ I/Q 생성
→ 파일 또는 SDR 전달
→ PocketSDR-AFS
→ AFS Frame 복원
```

목적:

- AFS 신호 생성부터 수신·복호까지 전체 체인 검증
- PRN 확산, 획득, 추적 및 복조 성능 확인
- 잡음과 도플러가 포함된 실제 수신 조건 시험

두 모드는 대체 관계가 아니다. Mode A는 데이터와 네트워크 계층을 빠르게 검증하는 시험이고, Mode B는 실제 AFS 신호처리 계층까지 포함한 종단 간 시험이다.

## 11. 오픈소스 재사용 시 구현 방향

부호화와 인터리빙 알고리즘을 C#으로 처음부터 다시 구현하기보다 LANS-AFS-SIM과 PocketSDR-AFS의 기존 코드를 재사용하는 것이 적절하다.

다만 원본 프로젝트는 최종적으로 I/Q 신호를 생성하거나 I/Q 신호를 수신하는 구조이므로, I/Q 없이 중간 심볼만 UDP로 보내려면 다음 인터페이스를 추가해야 한다.

### 송신기 수정 지점

```text
부호화·인터리빙 완료
→ BPSK 심볼/부호 비트 배열 추출
→ 비트 패킹
→ 파일, 표준 출력 또는 IPC로 WPF 프로그램에 전달
```

### 수신기 수정 지점

```text
WPF UDP 수신
→ 심볼 비트 언패킹
→ PocketSDR-AFS의 디인터리빙·복호 단계에 입력
```

이 중간 인터페이스는 기존 오픈소스의 기본 기능이 아니라, 네트워크 검증 프로그램을 위해 추가해야 하는 확장 기능이다.

## 12. 실행 예시

### LANS-AFS-SIM 빌드

```bash
git clone https://github.com/osqzss/LANS-AFS-SIM.git
cd LANS-AFS-SIM
make
```

### 기본 I/Q 파일 생성

```bash
./afs_sim -t 90 afssim_iq16.bin
```

### 2-bit I/Q 출력 모드

```bash
./afs_sim -t 90 -b 2 afssim_iq2.bin
```

`-b 2`는 I/Q 신호 파일의 출력 형식을 지정하는 옵션이다. 본 문서에서 제안한 `부호화 심볼 비트 패킹 UDP 모드`와는 다른 기능이다.

## 13. 결론

- LANS-AFS-SIM에는 AFS 프레임 구성, 오류 정정 부호화, 인터리빙, 심볼 매핑, PRN 확산 및 I/Q 생성 과정이 포함된다.
- PocketSDR-AFS에는 I/Q 수신 처리, 역확산, 심볼 추출, 디인터리빙, 오류 정정 복호 및 CRC 검사 과정이 포함된다.
- I/Q를 제외하고 부호화·인터리빙된 BPSK 심볼만 1비트씩 패킹하면, AFS 프레임 한 개를 일반적인 MTU 이내의 UDP 데이터그램 하나로 전달할 수 있다.
- 이 방식은 AFS RF/IQ 신호 시험이 아니라 AFS 채널 코딩 데이터와 Wi-Fi UDP 네트워크의 결합 시험이다.
- LDPC는 UDP 패킷 전체 유실을 복구하지 못하므로 반복 송신, 패킷 단위 FEC 또는 별도의 재전송 정책이 필요하다.
- 실제 AFS 신호처리까지 검증하려면 LANS-AFS-SIM의 I/Q 출력과 PocketSDR-AFS의 전체 수신 체인을 유지해야 한다.
