# PocketSDR-AFS 소스 코드 상세 설명

## 1. 한 문장 요약

`PocketSDR-AFS-main`은 범용 GNSS SDR 수신기 PocketSDR에 LANS AFS 신호 `AFSD`(data)와 `AFSP`(pilot), 6000심볼 프레임 복호, AFS LDPC, 달 궤도 기반 PVT를 추가한 수신기다.

주 프로그램 `app/pocket_trk/pocket_trk.c`는 SDR 장비 또는 I/Q 파일을 받아 신호 획득, 추적, 항법 데이터 복호, 관측값 생성, PVT와 로그 출력을 수행한다.

## 2. 위성·SDR 기초

### PRN, chip, symbol, I/Q

- PRN은 위성을 구분하는 확산 코드다. 같은 주파수의 여러 위성을 코드 상관으로 분리한다.
- chip은 PRN 코드의 빠른 단위다.
- 항법 symbol은 CRC·LDPC 후 데이터 채널에 실리는 0/1 단위다.
- I/Q sample은 확산·변조된 연속 신호를 일정 간격으로 수치화한 값이다.

이 코드에서 AFS symbol 하나는 2 ms다. AFSD primary code는 2046 chip/2 ms, AFSP는 10230 chip/2 ms다. 따라서 “1심볼=배열의 0/1 하나”는 맞지만 “1심볼=I/Q 샘플 하나”는 아니다. 12 MHz 입력에서는 한 symbol 동안 24,000 complex sample을 처리한다.

### 획득, 추적, 복호

- 획득(acquisition): PRN 코드 위상과 도플러 후보를 검색해 신호를 찾는다.
- 추적(tracking): 찾은 코드 위상과 반송파를 계속 따라간다.
- 심볼 판정: prompt 상관값 부호를 0/1로 바꾼다.
- 프레임 동기: 68심볼 SP의 위치와 정상/반전 극성을 찾는다.
- 복호: 디인터리빙, 천공 위치 복원, LDPC 복호, CRC 검사를 수행한다.

### 의사거리와 PVT

PRN 코드 도착시각으로 계산한 거리는 송수신 시계 오차까지 포함하므로 의사거리라고 부른다. AFS PVT 코드는 유효 궤도와 의사거리가 있는 위성이 최소 4개일 때 수신기 x/y/z와 수신기 시계 오차를 함께 계산한다.

## 3. 송신기와 수신기의 대응

```text
LANS-AFS-SIM                         PocketSDR-AFS
AFS payload 구성                     I/Q 파일 또는 장비 입력
CRC·LDPC·천공·인터리빙               PRN 상관으로 획득
PRN 확산과 I/Q 변조                  코드·반송파 추적
I/Q 출력                  →          심볼 판정과 프레임 동기
                                     디인터리빙
                                     erasure 삽입
                                     LDPC 복호와 CRC 검사
                                     SB2 궤도 해석과 PVT
```

## 5. 실제 호출 흐름

1. `pocket_trk.c`가 signal, PRN, 입력 형식과 샘플링 주파수를 파싱한다.
2. 파일은 `sdr_rcv_open_file()`, 장비는 `sdr_rcv_open_dev()`로 연다.
3. 채널마다 로컬 PRN 코드를 만든다.
4. `sdr_ch.c:search_sig()`가 FFT 기반 상관으로 코드 위상과 도플러를 찾는다.
5. `track_sig()`가 추적하면서 `sdr_nav_decode()`를 호출한다.
6. AFSD는 `decode_AFSD()`, AFSP는 `decode_AFSP()`로 분기한다.
7. AFSD는 6000심볼을 동기·복호하고 성공한 SB2를 `ch->nav->data`에 저장한다.
8. `sdr_pvt.c`가 `decode_afs_frame()`으로 궤도를 저장한다.
9. AFS 관측값이 있으면 `update_sol_afs()`가 PVT를 계산한다.

## 6. 실행

```sh
./pocket_trk -sig AFSD -prn 2-8 \
             -sig AFSP -prn 2-8 \
             -f 12 -IQ 2 -log log.txt input.bin
```

| 옵션 | 코드상 의미 |
|---|---|
| `-sig ... -prn ...` | signal과 PRN 채널 추가. 여러 번 반복 가능 |
| `-fmt INT8X2` | interleaved int8 I/Q. 기본 형식 |
| `-f 12` | 12 MHz 샘플링 |
| `-IQ 2` | I/Q sampling |
| `-fo` | RF 채널 LO 주파수 |
| `-toff`, `-tscale` | 파일 시작 offset과 재생 속도 |
| `-log`, `-nmea`, `-rtcm`, `-raw` | 출력 stream |
| `-InQ` | Q 부호 반전 |
| 파일 생략 | PocketSDR 장비 입력 |

LANS-AFS-SIM의 `-b 2` 출력은 I/Q 각각을 int8로 기록하므로 `INT8X2`, 12 MHz, IQ=2와 맞는다.

## 7. AFSD와 AFSP 코드

### 중심주파수

`src/pocket_sdr.h`의 `DEMO_L1`이 현재 활성화되어 있다. 따라서 `sdr_sig_freq()`는 AFSD/AFSP에 1575.42 MHz를 반환한다. 매크로를 제거하고 다시 컴파일하면 코드상 2492.028 MHz다. 실행 옵션이 아니라 컴파일 설정이다.

### AFSD data 채널

`gen_code_AFSD()`의 직접 확인값:

- PRN 1~210 허용
- G1 LFSR 인자 `0x7FF, 0x201, 11`
- G2 LFSR 인자 `0x7FF, 0x249, 11`
- PRN별 `AFSD_G2_delay[]`
- 출력 2046 chip, 주기 2 ms
- secondary code는 길이 1

### AFSP pilot 채널

`gen_code_AFSP()`는 `gen_code_L1CPD()`에 PRN별 Weil/삽입 index를 넣어 10230 chip, 2 ms primary code를 만든다. secondary code는 4 chip이며 PRN 1~12만 허용하고 네 개 고정 행을 `(prn-1)%4`로 선택한다.

현재 구현에서 중요한 사실:

- `AFSPT[210]` tertiary cache는 NULL로 초기화된다.
- `ter_code_AFSP()`는 있지만 호출부가 없다.
- `AFSPT`를 파일에서 읽거나 채우는 코드가 `src/`에 없다.
- `decode_AFSP()` 본문은 비어 있다.

따라서 현재 확실히 구현된 AFSP 범위는 primary/secondary 기반 획득·추적이다. tertiary 처리와 AFSP nav 복호는 활성 구현으로 확인되지 않는다.

## 8. 6000심볼 프레임 동기

수신 SP는 송신기와 같은 68비트다.

```c
{0xCC, 0x63, 0xF7, 0x45, 0x36, 0xF4, 0x9E, 0x04, 0xA0}
```

`decode_AFSD()`는 최신 prompt 상관값이 0 이상이면 1, 아니면 0으로 판정한다. 최신 6068심볼을 사용하며, 이는 6000심볼 프레임과 뒤의 다음 SP 68심볼을 검사할 수 있는 길이다. `sync_frame()`은 정상 및 반전 패턴을 확인해 `rev`를 반환한다.

`sync_AFS_SF1_FID0()`는 송신기와 같은 LFSR 방식으로 FID 0, TOI 0~99의 52심볼 후보를 만든다. SB1은 허용오차 0으로 전체 일치해야 한다. 현재 수신기는 다른 FID 또는 100 이상의 TOI 후보를 검색하지 않는다.

## 9. 디인터리빙과 subframe 분리

SP 68 + SB1 52 = 120심볼을 건너뛰고 다음 순서로 원래 배열을 복원한다.

```c
for (i = 0; i < 60; i++)
    for (j = 0; j < 98; j++)
        sf234[k++] = syms[j * 60 + i + 120] ^ rev;
```

결과는 다음 순서다.

```text
[SB2 2400][SB3 1740][SB4 1740] = 5880심볼
```

이는 송신기의 60×98 block interleaver를 정확히 역으로 되돌리는 index 관계다.

## 10. 천공 위치 erasure 복원

천공되어 수신하지 못한 위치는 0/1로 추측하지 않고 값 2인 `ERASURE`로 채운다.

### SB2

```text
[erasure 240][수신 2400][erasure 3600] = 6240
```

수신 2400 안에는 systematic 960 + p1 480 + p2 960이 들어 있다.

### SB3/SB4

```text
[erasure 176]
[수신 systematic 694]
[erasure filler 10]
[수신 p1 352 + p2 694 = 1046]
[erasure p2 2650]
= 4576
```

LDPC likelihood ratio 표에서 erasure의 ratio는 1.0이라 0과 1 어느 쪽도 선호하지 않는다.

## 11. LDPC와 큰 2차원 배열

`sdr_ldpc_afs.c`의 `SF2_A_ind`, `SF2_B_ind`, `SF2_C_ind`, `SF2_D_ind`, `SF3_...` 배열은 payload가 아니다. 각 `{행, 열}`은 sparse parity-check 행렬에서 값 1인 좌표다. `gen_AFS_LDPC_H()`가 이 좌표를 `mod2sparse_insert()`로 H 행렬에 넣는다.

`SF2_B_Inv_ind`와 `SF3_B_Inv_ind`도 선언되어 있지만 수신 H 행렬 생성에는 사용되지 않는다. 송신 인코더는 p1 계산에 B의 역행렬이 필요하지만, 수신기는 parity-check H를 만들기 위해 원래 B 좌표를 사용한다.

| 블록 | check 수 m | codeword n | 정보 길이 n-m |
|---|---:|---:|---:|
| SB2 | 5040 | 6240 | 1200 |
| SB3/SB4 | 3696 | 4576 | 880 |

`decode_B_LDPC()`는 LDPC-codes 라이브러리의 probability propagation decoder를 사용한다. 최대 반복은 250, 가정 오류확률은 1e-5로 하드코딩되어 있다. parity check가 맞으면 변경 비트 수, 실패하면 -1을 반환한다.

- SB2 출력의 앞 1200비트를 CRC 검사한다.
- SB3/SB4 출력의 앞 870비트를 CRC 검사한다.
- SB3/SB4의 정보 길이 880 중 마지막 10비트는 filler다.
- 라이브러리가 thread-safe하지 않다는 코드 주석 때문에 AFS LDPC 호출을 mutex로 직렬화한다.

## 12. CRC24Q

`test_CRC()`는 마지막 24비트를 포함한 배열을 byte pack하고 RTKLIB `rtk_crc24q()`를 사용한다.

- SB2: 1200비트 검사
- SB3/SB4: 870비트 검사

LDPC 반환값이 0 이상이고 CRC도 맞아야 성공이다. LDPC는 오류를 정정하고 CRC는 남은 오류를 검출한다.

## 13. SB2 시간·궤도 해석

SB2 성공 시 `decode_AFSD_frame()`은:

- WN: bit 0부터 13비트
- ITOW: bit 13부터 9비트
- 시간: `ITOW*1200 + TOI*12 + 0.136초`

로 설정한다. 0.136초는 SP 68심볼 × 2 ms다. 복호된 1200비트를 150바이트로 pack하여 `ch->nav->data`에 저장하고 nav type을 2로 설정한다.

`sdr_pvt.c`는 AFSD type 2를 받으면 `decode_afs_frame()`을 호출한다. 이 함수는 송신기와 같은 scale로 다음 값을 역변환한다.

| 필드 | 길이 | 역변환 |
|---|---:|---|
| WN | 13 | 그대로 |
| ITOW | 9 | 궤도 parser에서는 건너뜀 |
| toe | 16 | ×16초 |
| ecc | 32 | ×2^-32 |
| sqrt(A) | 32 | ×2^-19 |
| inc0, RAAN, aop, m0 | 각 32 | signed ×2^-31×π |
| toc | 16 | ×16초 |
| af0 | 22 | signed ×2^-31 |
| af1 | 16 | signed ×2^-43 |

비트 284 이후는 궤도 해석에 사용하지 않는다.

## 14. SB3와 SB4의 수신 처리

SB3와 SB4도 각각 erasure 복원, LDPC 복호, 870비트 CRC 검사를 수행한다. 성공하면 `$SB3 ... FRAME DECODED`, `$SB4 ... FRAME DECODED`를 기록한다.

현재 소스에는 복호된 SB3/SB4 846비트 payload를 서비스 메시지로 해석하거나 상위 기능으로 전달하는 코드가 없다. 송신기 역시 두 payload를 시험 패턴으로 채우므로 현재 종단간 시험은 두 subframe의 물리/채널 부호 계층 성공 여부를 확인하는 성격이다.

## 15. AFS PVT

`sdr_pvt_udsol()`은 관측값에 `CODE_L9D`가 하나라도 있으면 일반 RTKLIB `pntpos()` 대신 `update_sol_afs()`를 호출한다.

`update_sol_afs()`의 실제 순서:

1. 유효 AFS ephemeris가 있는 관측 위성을 순회하고 첫 번째 유효 code의 pseudorange를 저장한다.
2. 위성이 4개 미만이면 해를 만들지 않는다.
3. 초기 위치는 달 남극 `(0, 0, -R_MOON)`, 수신기 시계 오차는 0이다.
4. 위성별 예상 의사거리와 위치 편미분을 계산한다.
5. 4×4 normal matrix를 가우스 소거로 역행렬화한다.
6. x/y/z와 수신기 시계 보정량을 4회 반복 갱신한다.
7. 달 반지름 구 모델의 위도·경도·고도로 바꿔 `$POS`를 출력한다.

`decode_afs_frame()`은 궤도를 저장할 뿐이고 PVT 계산은 후속 `update_sol_afs()`가 실제로 담당한다.

중요한 제한: `satpos()`는 위성 시계 `clk`를 계산하지만 `computeRange()`의 예상 의사거리에는 `-dt_sat*c` 항이 주석으로 남아 있어 실제 적용되지 않는다.

## 16. 송수신 비교 로그

현재 수정본은 PRN 8에서 SB2 LDPC와 CRC가 성공한 처음 2개 프레임만 상세 기록한다.

| 비교 ID | 수신 단계 | 비교 기준 |
|---|---|---|
| `C001` | 극성 보정 SP 68 | 송신 SP 전체 |
| `C101-Txx` | SB1 52 | 같은 TOI 송신 SB1 |
| `C201-P08` | SB2 payload 1176 | 송신 CRC 입력 |
| `C202-P08-CRC` | 프레임 CRC와 재계산 CRC | 송신 CRC |
| `C202-P08` | SB2 복호 1200 | 송신 CRC 포함 데이터 |
| `C203-P08-ERASURE` | 6240 LDPC 입력 | E가 아닌 위치만 송신 codeword와 비교 |
| `C204-P08` | SB2 수신 2400 | 송신 천공 결과 |
| `C301~C304` | SB3 단계 | 송신 동일 단계 |
| `C401~C404` | SB4 단계 | 송신 동일 단계 |
| `C501-P08` | 디인터리빙 5880 | 송신 인터리빙 전 |
| `C502-P08` | 인터리빙 상태 5880 | 송신 인터리빙 후 |
| `C601-P08-Txx` | 극성 보정 6000 | 같은 TOI 송신 프레임 |

erasure는 애초에 수신하지 않은 위치이므로 송신 전체 codeword와 전체 일치를 요구하면 안 된다. E가 아닌 위치만 비교해야 한다.

일반 로그:

- `$SB2`: 성공한 SB2 1200비트의 16진수
- `$SB3`, `$SB4`: subframe 성공
- `$POS`: AFS PVT
- `AFSD SBx FRAME ERROR`: LDPC 또는 CRC 실패
- `TOI NOT FOUND`: SB1 후보 불일치

## 18. 코드에서 확인된 제한과 주의점

1. `decode_AFSP()`는 빈 함수다.
2. AFSP tertiary cache를 채우거나 적용하는 호출 경로가 없다.
3. SB1은 FID 0, TOI 0~99만 검색하고 52심볼 완전 일치만 허용한다.
4. SB2 실패 시 `unsync_nav()`로 nav sync를 해제한다.
5. SB3/SB4 실패는 오류 로그를 남기지만 성공한 SB2 nav 저장을 취소하지 않는다.
6. 성공 시 `ch->nav->nerr=0`으로 강제하며 코드에 `FIXME`가 있다.
7. AFS PVT는 매 epoch 남극 초기값에서 시작하며 이전 해를 초기값으로 쓰지 않는다.
8. AFS PVT 예상 의사거리에 위성 시계 보정이 적용되지 않는다.
9. 달은 반지름 고정 구로 취급한다.
10. `decode_afs_frame()`은 `sv >= MAX_SAT`만 검사하여 PRN 0의 음수 index는 직접 방어하지 않는다. 정상 채널은 양수 PRN을 쓴다.
11. nav symbol은 prompt 상관값 부호 하나로 hard decision한다.
12. AFS LDPC H cache는 프로세스 수명 동안 재사용하며 해제 경로가 확인되지 않는다.
13. PVT 관측 loop는 유효 ephemeris를 확인한 뒤 pseudorange code를 못 찾은 경우에도 `nsat++`를 실행한다. 정상 관측 구조에서는 code가 존재한다는 전제처럼 동작하지만, 방어적으로는 code 발견 여부를 별도로 확인해야 한다.

## 19. 빌드 주의점

Ubuntu/WSL 공식 흐름:

```sh
sudo apt install libusb-1.0-0-dev libfftw3-dev
cd lib && ./clone_lib.sh
cd build && make && sudo make install
cd ../../app/pocket_trk && make
```

Windows makefile은 `libsdr.a`, `librtk.a`, `libfec.a`, `libldpc.a`, FFTW3f, pthread, CyUSB와 Windows system library를 링크한다. `src/`를 수정하면 `lib/build/libsdr.a`를 먼저 다시 만든 뒤 `pocket_trk`를 재링크해야 수정이 반영된다.
