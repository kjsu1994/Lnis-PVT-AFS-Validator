# AFS 송신·수신 로그 확인 방법

## 1. 문서 목적

이 문서는 `LANS-AFS-SIM-main`에서 생성한 송신 로그와 `PocketSDR-AFS-main`에서 생성한 수신 로그를 사람이 직접 비교하여 다음 처리가 정상인지 확인하는 방법을 설명한다.

- AFS 전체 6000심볼 구성
- 동기 패턴과 SB1
- SB2, SB3, SB4 원본 데이터와 CRC24
- LDPC 부호화와 천공
- SB2~SB4 결합과 인터리빙
- 수신측 디인터리빙과 erasure 복원
- LDPC 복호와 CRC24 재검사

현재 상세 로그는 **PRN 8**을 대상으로 하며, 수신측은 **SB2 LDPC 복호와 CRC24 검사가 성공한 프레임부터 최대 2회** 기록한다.

### 송신 로그

```text
O:\3.ing\LNIS\LnisAfsValidator\오픈소스\LANS-AFS-SIM-main\afs_sim_log.txt
```

### 수신 로그

```text

```

두 로그는 프로그램을 실행할 때 새로 작성된다. 소스를 수정한 경우 송신기 또는 수신 라이브러리와 실행 파일을 다시 빌드해야 수정 내용이 로그에 반영된다.

## 3. 로그 한 줄 읽는 방법

예시:

```text
[송신][비교ID=C101-T27][PRN=공통][TOI=27][SB01][단계=FID=0, TOI 기반 SB01][길이=52][비트범위=0000-0051]
비트=...
16진수=...
```

| 항목 | 의미 |
|---|---|
| `송신` / `수신` | 데이터가 기록된 위치 |
| `비교ID` | 송신과 수신에서 같은 데이터를 찾기 위한 식별자 |
| `PRN=08` | PRN 8 채널의 데이터 |
| `PRN=공통` | 모든 PRN에 동일하게 사용되는 데이터 |
| `TOI` | 12초 단위 AFS 프레임 시간 번호, 범위 0~99 |
| `SB01`~`SB04` | AFS Subframe 번호 |
| `단계` | CRC, LDPC, 천공, 인터리빙 등 현재 데이터의 처리 단계 |
| `길이` | 배열 전체 길이, 단위는 비트 또는 이진 심볼 |
| `비트범위` | 현재 로그 조각에 포함된 배열 인덱스, 양 끝 포함 |

긴 배열은 256비트 단위로 나뉜다. 예를 들어 길이 6000은 다음처럼 기록된다.

```text
0000-0255
0256-0511
...
5888-5999
```

같은 `비교ID`의 같은 `비트범위`끼리 비교해야 한다.

## 4. 비트와 16진수

각 조각에는 같은 값을 두 가지 형식으로 기록한다.

```text
비트=010101...
16진수=55...
```

- `비트=`가 원본 값이며 가장 정확한 비교 기준이다.
- `16진수=`는 사람이 더 짧게 비교하기 위한 표현이다.
- 길이가 4의 배수가 아닌 데이터는 마지막 16진수 자리에 패딩이 포함될 수 있으므로 최종 판정은 `비트=`를 기준으로 한다.
- 수신측 `E`는 천공으로 인해 전송되지 않아 수신할 수 없는 erasure 위치다.
- `E`가 포함된 조각은 `16진수=해당없음(erasure 포함)`으로 기록된다.

## 5. 비교ID 전체 의미

| 비교ID | 송신 단계 | 대응하는 수신 단계 | 직접 일치 기준 |
|---|---|---|---|
| `C001` | 동기 패턴 68비트 | 극성 보정 후 동기 패턴 | 전체 일치 |
| `C101-Txx` | 해당 TOI의 SB1 52비트 | 수신 SB1 | 같은 TOI끼리 전체 일치 |
| `C201-P08` | SB2 CRC 입력 1176비트 | SB2에서 복호된 CRC 입력 데이터 | 전체 일치 |
| `C202-P08-CRC` | SB2 송신 CRC24 | 프레임 내 CRC24와 수신측 재계산 CRC24 | 세 값 일치 |
| `C202-P08` | SB2 데이터+CRC 1200비트 | SB2 LDPC 복호 후 1200비트 | 전체 일치 |
| `C203-P08-SYS` | SB2 LDPC systematic | 복호 전 송신 기준값 | 참고용 |
| `C203-P08-P1` | SB2 LDPC p1 | 복호 전 송신 기준값 | 참고용 |
| `C203-P08-P2` | SB2 LDPC p2 | 복호 전 송신 기준값 | 참고용 |
| `C203-P08` | SB2 전체 LDPC 코드워드 6240비트 | `C203-P08-ERASURE` | 수신측에서 `E`가 아닌 위치만 일치 |
| `C204-P08` | SB2 천공 후 2400심볼 | 디인터리빙 후 분리한 SB2 | 전체 일치 |
| `C301` | SB3 CRC 입력 846비트 | SB3 복호 데이터 846비트 | 전체 일치 |
| `C302-CRC` | SB3 CRC24 | 수신·재계산 CRC24 | 일치 |
| `C302` | SB3 데이터+CRC 870비트 | SB3 LDPC 복호 후 | 전체 일치 |
| `C303-*` | SB3 LDPC 내부값과 전체 코드워드 | `C303-ERASURE` | `E`가 아닌 위치만 일치 |
| `C304` | SB3 천공 후 1740심볼 | 분리된 수신 SB3 | 전체 일치 |
| `C401`~`C404` | SB4의 CRC·LDPC·천공 단계 | 수신 SB4의 동일 단계 | SB3과 같은 방법 |
| `C501-P08` | 인터리빙 전 SB2~SB4 5880심볼 | 수신 디인터리빙 후 5880심볼 | 전체 일치 |
| `C502-P08` | 인터리빙 후 5880심볼 | 인터리빙 상태 수신 심볼 | 전체 일치 |
| `C601-P08-Txx` | 최종 AFS 프레임 6000심볼 | 극성 보정 후 수신 AFS 프레임 | 같은 TOI끼리 전체 일치 |

`xx`는 실제 TOI 번호다. `C101-T27`을 `C101-T26`과 비교하면 안 된다.

## 6. 권장 비교 순서

### 6.1 상세 로그가 완성됐는지 확인

수신 폴더에서 다음 명령을 실행한다.

```powershell
Select-String .\log.txt -Pattern "\[상세로그="
```

정상적인 경우 다음 항목이 최대 두 번 나온다.

```text
[상세로그=1/2]
[상세로그=2/2]
```

다음 명령으로 수신 비교ID 종류를 확인한다.

```powershell
Select-String .\log.txt -Pattern "^\[수신\]\[비교ID=" |
    ForEach-Object {
        if ($_.Line -match "비교ID=([^\]]+)") { $Matches[1] }
    } |
    Sort-Object -Unique
```

`C001`부터 `C601`까지 필요한 ID가 없다면 해당 단계의 상세 로그가 완성되지 않은 것이다.

### 6.2 전체 프레임 확인: C601

먼저 수신 로그에서 TOI를 찾는다.

```powershell
Select-String .\log.txt -Pattern "비교ID=C601-P08-"
```

수신이 `C601-P08-T27`이라면 송신에서도 정확히 같은 ID를 찾는다.

```powershell
Select-String `
    "O:\3.ing\LNIS\LnisAfsValidator\오픈소스\LANS-AFS-SIM-main\afs_sim_log.txt" `
    -Pattern "비교ID=C601-P08-T27" -Context 0,2

Select-String .\log.txt `
    -Pattern "비교ID=C601-P08-T27" -Context 0,2
```

모든 `비트범위`의 `비트=` 값이 같으면 동기 패턴, SB1, 인터리빙된 SB2~SB4를 포함한 최종 6000심볼이 일치한다.

### 6.3 인터리빙 확인: C502와 C501

1. `C502-P08` 비교
   - 송신: 인터리빙 후
   - 수신: 인터리빙 상태 수신 심볼
   - 전체가 같으면 전송·복조 후 인터리빙 배열이 보존된 것이다.

2. `C501-P08` 비교
   - 송신: 인터리빙 전
   - 수신: 디인터리빙 후
   - 전체가 같으면 수신 디인터리빙이 송신 인터리빙을 정확히 되돌린 것이다.

검색 예시:

```powershell
Select-String .\log.txt -Pattern "비교ID=C502-P08" -Context 0,2
Select-String .\log.txt -Pattern "비교ID=C501-P08" -Context 0,2
```

### 6.4 SB2 천공 확인: C204

송신 `C204-P08`은 LDPC 전체 코드워드에서 규격에 따라 일부를 제외하고 실제 전송한 2400심볼이다.

수신 `C204-P08`은 5880심볼을 디인터리빙한 뒤 SB2 구간 2400심볼을 분리한 값이다.

두 값이 모두 같으면 다음 처리가 정상이다.

- 송신 SB2 천공 결과
- SB2~SB4 결합
- 인터리빙과 전송
- 수신 디인터리빙
- SB2 구간 분리

### 6.5 SB2 LDPC 복호와 CRC 확인: C203, C202, C201

1. `C203-P08-ERASURE`
   - 천공되어 전송되지 않은 위치는 `E`다.
   - `E`가 아닌 위치는 송신 `C203-P08` 전체 코드워드의 같은 인덱스와 같아야 한다.
   - 이 배열 전체를 송신 코드워드와 문자열 그대로 비교하면 안 된다.

2. `C202-P08`
   - 송신의 1200비트 CRC 포함 입력과 수신 LDPC 복호 후 1200비트를 비교한다.
   - 전체 일치해야 한다.

3. `C201-P08`
   - CRC를 제외한 원본 1176비트를 비교한다.
   - 전체 일치해야 한다.

4. `C202-P08-CRC`
   - 송신 계산값
   - 수신 프레임에 들어 있던 CRC24
   - 수신측 재계산 CRC24
   - 위 세 값이 모두 같고 `CRC24 비교 결과=일치`여야 한다.

### 6.6 SB3 확인: C301~C304

SB3은 다음 순서로 확인한다.

```text
C304: 천공 후 전송 심볼 일치
C303: erasure가 아닌 LDPC 입력 위치 일치
C302: LDPC 복호 후 870비트 일치
C302-CRC: CRC24 일치
C301: CRC를 제외한 846비트 원본 일치
```

현재 송신기는 SB3 원본에 `0,1,0,1,...` 시험 패턴을 사용한다.

### 6.7 SB4 확인: C401~C404

SB4는 SB3과 같은 방식으로 비교한다.

```text
C404: 천공 후 전송 심볼
C403: LDPC 전체 코드워드와 erasure 입력
C402: LDPC 복호 후 데이터+CRC
C402-CRC: CRC24
C401: 원본 846비트
```

현재 송신기의 SB3과 SB4는 같은 시험 패턴을 사용하지만, 로그에서는 서로 다른 비교ID로 구분한다.

### 6.8 SB1과 TOI 확인: C101

송신 예시:

```text
[송신][비교ID=C101-T27][PRN=공통][TOI=27][SB01]...
```

수신에서는 다음을 찾는다.

```text
[수신][비교ID=C101-T27][PRN=08][TOI=27][SB01]...
```

`PRN=공통`과 `PRN=08`이 다른 것은 정상이다. 송신기는 동일 SB1을 모든 PRN에 사용하고, 수신기는 PRN 8 채널에서 이를 추출하기 때문이다.

52비트 전체가 같으면 SB1 생성, 송수신, 극성 보정, 프레임 경계와 TOI 판정이 정상이다.

## 7. 정상 판정 기준

다음 조건을 모두 만족하면 해당 AFS 처리 경로가 정상이라고 판정한다.

- `C001` 동기 패턴 일치
- 같은 TOI의 `C101` SB1 일치
- 같은 TOI의 `C601` 전체 6000심볼 일치
- `C502` 인터리빙 상태 일치
- `C501` 디인터리빙 결과 일치
- `C204`, `C304`, `C404` 천공 심볼 일치
- LDPC erasure 입력의 `E`가 아닌 위치 일치
- `C202`, `C302`, `C402` LDPC 복호 결과 일치
- `C201`, `C301`, `C401` CRC 제외 원본 일치
- 모든 CRC24 수신값과 재계산값 일치
- `$SB2`, `$SB3`, `$SB4` 성공 로그가 존재하고 `AFSD SBx FRAME ERROR`가 없음

## 8. 불일치 해석

| 현상 | 의심 단계 |
|---|---|
| `C001` 불일치 | 프레임 동기 또는 극성 보정 |
| `C101` 불일치 | SB1 생성, 프레임 경계 또는 TOI 판정 |
| `C601` 불일치, `C502` 불일치 | 복조 또는 전체 프레임 정렬 |
| `C502` 일치, `C501` 불일치 | 수신 디인터리빙 |
| `C501` 일치, `C204/C304/C404` 불일치 | SB 구간 분리 인덱스 |
| 천공 심볼 일치, LDPC 실패 | erasure 위치 복원, LDPC 행렬 또는 복호기 |
| LDPC 복호 결과 일치, CRC 불일치 | CRC 정렬·계산·추출 |
| 52비트 또는 전체 프레임이 모두 반전 | 수신 극성 보정 |
| 비교ID의 TOI가 다름 | 서로 다른 프레임을 비교한 것 |

## 9. 주의사항

- 반드시 송신기와 수신기를 최신 소스로 다시 빌드한 결과를 사용한다.
- 송신과 수신의 `비교ID` 및 `비트범위`가 같은지 먼저 확인한다.
- TOI가 포함된 ID는 같은 TOI끼리만 비교한다.
- `PRN=공통`은 PRN 8과 비교할 수 있는 공통 데이터다.
- erasure 배열은 `E` 때문에 전체 문자열이나 16진수를 직접 비교하지 않는다.
- 수신 상세 로그는 PRN 8의 성공 프레임 최대 2회만 기록한다.
- 로그 중간에 일반 `$TIME`, `$OBS`, `$SB2`, `$SB3`, `$SB4` 로그가 있어도 비교ID가 붙은 조각만 골라 비교한다.
- 최종 비트 수가 4의 배수가 아니면 16진수 마지막 자리보다 `비트=` 값을 우선한다.
